# 生成策略 — 怎么让图像模型服从空间约束

知识条文（geometry）解决「什么是对的」，本文解决「怎么让模型做到」。
这是整个 skill 最容易被忽略、也最决定成败的部分。

## 0. 先认清生成的本质

图像模型**没有三维推理能力**，它做的是「按描述统计性地铺像素」。
所以：

- 「机位在 A 的右前方 45°」这类参数化描述，模型只能**部分**服从
- 真正可靠的是**视觉锚 + 显式约束 + 事后校验迭代**
- 策略目标不是「一次画对」，是「**每一轮都可验证、可收敛**」

**这不是经验之谈，是研究结论**（详见 research-notes.md §2）：

- 文生图模型无法把焦距参数翻译成一致透视（arXiv:2412.02168）
- 用 4 个相机参数显式条件化，效果就**超过提示词工程**（PreciseCam,
  arXiv:2501.12910）——自然语言描述机位的精度天花板就这么高
- 文本-视觉隐空间里没有「相机左转 45°」这个概念（arXiv:2604.19954），
  但有「右肩入画」这类画面统计 → 所以**描述画面结果，不描述相机运动**
- 真正的多视角一致要么改架构（MV-Adapter 等），要么联合生成多图；
  通用模型 + 提示词时，本 skill 的管线就是上限，不要承诺「一次全对」

## 1. 生成链路选择（按可靠性排序）

| 链路 | 适用 | 空间控制力 | 说明 |
|---|---|---|---|
| a. 图生图 + 参考图（单一正反打图） | 所有场景默认 | ★★★ | 首选。画面内容有锚，只需改机位 |
| b. 多参考图（正打+反打一起喂） | 需要跨镜信息时 | ★★★ | 两张图信息互补，但注意模型可能「拼贴」而非重构 |
| c. 纯文生图 | 参考图质量太差时 | ★ | 最后手段。只靠文字，透视基本靠抽 |
| d. 生成 + 局部重绘（inpaint 修违例） | 修小问题（道具漂移、单人翻转） | ★★★★ | 修正协议的主力工具，见 §5 |
| e. 几何管线（深度→反投影→渲染→补洞） | 要求极高一致性 | ★★★★★ | 数学级透视。完整方案见 `geometric-pipeline.md`；草图定构图是其轻量替代 |

**决策规则**：默认走 a；同一场戏 ≥4 个机位时建议 e；
单张图小违例优先 d 局部修，别整图重抽。

## 2. 提示词结构（三明治法）

```
【锁定块】    ← 每张图逐字相同（空间锚点 + 禁止变化清单）
【机位块】    ← 本机位的五要素 + 视线锁定
【画面块】    ← 本机位能看到的内容、动作、情绪
【禁止块】    ← 负面清单（针对本机位的高发违例）
```

关键技巧：

1. **锁定块放最前**——注意力权重最高的位置留给一致性信息
2. **用「必须保持」而非「不要改变」**——「A 始终在画面左侧」比「不要翻转 A」有效；
   否定句在扩散模型里效果弱，禁止块只作辅助
3. **描述画面结果，不描述相机运动**——写「A 的右侧脸轮廓可见」而非
   「相机向左转 45°」（模型不懂旋转指令，只懂画面结果）
4. **把几何翻译成视觉特征**——「35mm」模型可能不认，但「轻微透视、
   背景可见整面墙、肩与头比例自然」它认。**焦距写两遍**：参数一遍 +
   视觉效果一遍

## 3. 机位的两种表述法（都写进机位表）

**参数式**（给人看，机器辅助校验用）：
> 方位：B 右前方 45°；高度 1.3m；焦距 35mm；过 A 肩

**画面式**（给模型看，生成提示词用）：
> 画面左下有 A 的右肩后脑（占画面约 15%），B 面朝画面左、胸口以上入画，
> 背景右侧窗户可见，桌面红色水杯在 B 手边。视平线约在画面高度 40% 处。

Step 2 的机位表**两列都要有**。生成时以画面式为主、参数式为辅。

## 4. 生成顺序：锚点先行

不要按机位表顺序盲跑。顺序应该是：

1. **M3 总机位**先出（信息最全，纠错最容易）——人工确认这帧的空间关系对
2. 以 M3 为参考图，出**正反打（M1/M2）**，核对与原参考图的锁定项
3. 其余机位（M4–M7）逐一出，每张都以「原始正反打图 + 已确认的 M3」为参考
4. 每张出完立即过自检清单，**过了才下一张**（防止错误雪崩）

批量并行生成只用于「同一机位多抽几张选优」，**不同机位不要并行盲出**。

## 5. 修正协议（违例了怎么办）

原则：**最小改动修正，不整图重抽**。

| 违例类型 | 首选手段 | 操作 |
|---|---|---|
| 左右位置翻转 | 局部重绘（d） | 只重绘翻转的人物/区域，锁定块不变 |
| 道具漂移 | 局部重绘（d） | 重绘道具所在小区域 |
| 焦距/透视整体错 | 整图重生成 | 锁定块里把焦距的**视觉效果**描述加倍强调 |
| 地平线错 | 整图重生成 | 机位块里显式写「视平线在画面高度 N%」 |
| 视线方向错 | 局部重绘（d） | 只重绘眼部/头部 |
| 整体乱（多项违例） | 整图重生成 | 先判断是不是机位描述本身有歧义，改机位表再跑 |

修正时**追加针对性约束句**到禁止块，例如：
> 本图修正项：A 必须位于画面左 1/3 且面朝右；上一版错误是 A 出现在右侧。

**每张图记录**：机位号 → 抽卡次数 → 违例史 → 最终手段。这张表是给用户看的
交付物的一部分，也是调参依据。

## 6. 抽卡预算（管理预期）

参考 `ai-shortfilm-prompts` 的经验值：简单镜头 2–3 次，复杂机位（大俯拍、
多前景遮挡、侧面）20+ 次是正常的。**批量任务前先按机位难度估预算**，
向用户报「预计生成 N×M 次」，不要跑一半才发现成本失控。

降抽卡率的三个手段（按优先级）：
1. 提高机位描述的画面式精度（§3）
2. 用锚点先行顺序（§4）
3. 换 e 链路（几何管线，见 `geometric-pipeline.md`）

## 7. 针对特定模型的适配点

模型能力差异很大，动手前先试 2 张探底：

- **强参考图模型**（如 nano banana / Seedream 图生图）：参考图权重高，
  机位块写简短画面式即可，锁定块重点写「变化项 vs 不变项」边界
- **文生图强模型**（如 Midjourney 纯 t2i）：参数式焦距/景别词（`35mm`, `OTS`）
  有奇效，但跨图一致性弱，必须依赖锚点先行 + 高抽卡预算
- **有 camera control 的模型/插件**（ComfyUI 里带相机节点、Depth/Normal 控制、
  PreciseCam 类参数条件化）：直接把机位表的**参数式列**喂给控制节点
  （PreciseCam 约定：焦距 1 个内参 + 机位/旋转 3 个外参，共 4 参数），
  提示词只管内容——这是唯一能真正「锁透视」的路径，成本是搭建复杂。
  研究表明参数条件化精度显著超过提示词工程（arXiv:2501.12910）
- **中文提示词模型 vs 英文**：术语用该模型文档推荐的语言；
  空间方位词（左/右）在两种语言里都要显式写，不要依赖默认构图
