# 多视角几何 — 为什么这样设计管线

给改动者和想深究的使用者：本文解释本 skill 每条设计背后的数学理由。
不参与日常运行，但改管线前应读懂——否则容易「优化」掉某个关键约束。

## 1. 一张图 = 一次投影

```
x = K [R | t] X

X     = 3D 世界中的点（真实存在：「桌上红色水杯的杯盖」）
x     = 它落在照片上的像素位置
K     = 内参（焦距、主点）——镜头怎么折光
R, t  = 外参——机位在哪、朝哪、什么姿态
```

**一张照片**：场景每个点 Xᵢ 投影出像素 xᵢ。
**多视角（multi-view）**：同一批 Xᵢ，被不同的 (R, t) 投影出多组像素。

严格定义：**共享同一个 3D 场景 X 的多张图，区别只在相机参数。**

## 2. 正反打图是什么（输入数据的身份）

正反打图 = 场景的两张**实际画面**（照片或照片级生成图），不是机位示意图：

```
同一场景 X
  ├─ 相机 1: 内参 K（同一支镜头）、外参 (R1,t1)（B 的外侧后方）→ 正打图（过 B 肩拍 A）
  └─ 相机 2: 内参 K（同一支镜头）、外参 (R2,t2)（A 的外侧后方）→ 反打图（过 A 肩拍 B）
```

「共享内参、不同外参」是解释两张图关系的**数学假设**：

- 一台机器挪机位拍两次 → 假设天然成立（同机身镜头）
- 双机同拍 → 近似成立（匹配镜头 + 标定）；电影视线匹配规范要求正反打
  两镜「同焦距、同高度、同距离」，就是为了让它成立
- **AI 生成的图 → 只是约定**。没有 EXIF、没有标定。「共享内参」是愿望不是事实

→ 这就是 Step 1 反推的意义：**从像素估计**这组 K/R/t，而不是读取。
两张图明显不同焦距感 = 素材不规范，走 uncertain 报告用户。

## 3. 视图之间的三层几何关系

### 3.1 对极几何 — 「点在某条线上」

两视图对应点满足 `x₂ᵀ E x₁ = 0`（E = 本质矩阵，由相对位姿和 K 决定）：

```
        C1 ●              ● C2          ← 两个机位
            ╲    P ●     ╱
             ╲   3D点  ╱
              ╲       ╱
图1: p1 ●      ╲     ╱      ● 图2: p2 必落在极线 l2 上
                ╲   ╱
```

含义：图 1 的一个点，在图 2 里**必落在极线上**，但不知具体位置。
**不需要深度**就能用——纯几何质检工具：多机位图里对应物体不落在极线上 ⇒
两图必有一张透视错。

### 3.2 三角化 — 「两图匹配 → 3D 点」

同一对点在两图中都找到 → 两条极线空间相交 → P = (X,Y,Z) 恢复。
这是 SfM（Structure from Motion）的核心。

限制：只有**两图都看见**的点能恢复；尺度不确定（整体放大 2 倍投影不变，
除非有参照物）；两机位夹角越小深度误差越大（正反打夹角通常不大 → 深度不精）。

### 3.3 重投影 — 「3D 点 + 新机位 → 新图位置」

有了深度，指定新机位 (R',t')，每个点在新图上的位置直接算：

```
P ──投影到 (R',t')──►  x' = K[R'|t'] P
```

这就是**渲染**。游戏引擎每秒做几百万次。
**几何上完全正确的多机位图就是这么来的**——这解释了路线 A 为何可靠。

## 4. 「透视关系怪」的数学翻译

「多视角一致」= **所有图共享同一个 X**。自检清单的违例各对应什么：

| 现象 | 数学上发生了什么 |
|---|---|
| 人物左右翻转 | 新图 R 放到了轴线另一侧，或根本没共享 X |
| 地平线漂移 | 机位高度 t_y 或 K 变了 |
| 焦距忽广忽长 | K 变了 |
| 道具换位 | 道具的 X 不一样——是两个场景 |
| 遮挡顺序错乱 | 各图的深度排序不相容，X 的相对位置变了 |

→ perspective-checklist 的 18 项本质是在查：**这批图是不是同一组 X 的不同投影**。

## 5. 信息边界 — 为什么不能纯流程化

两张正反打图只覆盖一个有限的可见区：

```
        A ●━━━━━━━━━━━━● B
           ╲  可见区  ╱    ← 正反拍得到的面：A/B 正面、朝镜头那侧的
            ╲        ╱        家具、背景
        ──────────────────
             ╲ 未见区╱       ← A 的后背、书架侧面、桌面远端、被挡住的一切
              ╲    ╱           信息在输入里不存在
```

- **可见区**：深度可估、重投影可靠 → 数学管
- **未见区**：**信息不存在**，任何新机位露出这里就必须「编」→ 生成管

正反打机位靠得近，未见区相当大——换到侧面/高角机位时画面可能近半是
没拍过的东西。**这就是「数学关系存在但无法全自动」的根本原因**：
数学只能搬运已知，未知必须幻想，而幻想正是透视最容易崩的地方。

## 6. 三个病态问题

1. **恢复 3D 病态**：单目深度有尺度/歧义；弱纹理（白墙、纯色衣服）匹配失败；
   两机位夹角小 → 三角化深度不准
2. **补未见区病态**：没有唯一正确答案（A 的后背长什么样？无数种都「对」），
   生成模型靠统计幻觉，不带几何约束
3. **模型不吃几何参数**：提示词写「右转 45°」，扩散模型隐空间里没有旋转算子
   （research-notes §2），它只学过「45° 的图像长什么样」的统计

## 7. 三条路线的定位（详细决策见 prompt-strategy §1）

| 路线 | 做法 | 透视 | 成本 | 未见区 |
|---|---|---|---|---|
| A. 几何管线 | 深度→位姿→重建→**渲染**→补洞 | 数学级准 | 高 | 显式空洞，定向补 |
| B. 多视角生成模型 | MV-Adapter/MVDream/CAT3D/世界模型 | 训练级一致 | 中 | 模型幻想 |
| C. 机位图+提示词（本 skill） | 共享空间描述+锚点+校验迭代 | 软约束+兜底 | 低 | 锁定块+人工核对 |

**混合是实战答案**：高要求镜头用 A 出底图、批量覆盖用 C、
模型生态允许时整场戏用 B。本 skill 是 C 的上限方案，必要时按 prompt-strategy
§1 升级到 A/B 并复用同一份机位表（机位表与路线无关，是三路线共享的产物）。

## 8. 本 skill 各设计的数学出处

| 设计 | 在守什么 |
|---|---|
| 《机位图》物化共享空间 | 共享 X —— 否则每张图是独立场景 |
| 轴线规则 / 过肩不变量 | R 的合法性 —— 机位放错直接翻转投影 |
| 焦距双写（参数+视觉效果） | K —— 模型不认参数，认视觉统计 |
| 锚点先行（M3→正反打→其余） | 控制误差传播 —— 从信息最全的视图出发 |
| 禁止生成图互喂 | 防 X 的估计误差累积 |
| 18 项自检 + 修正协议 | 兜底病态问题 1/2/3 —— 幻觉可检测、最小改动修正 |
| uncertain 不生成 | 病态问题 1 —— 错的 K/R/t 污染整批图 |

## 9. 术语速查

| 术语 | 英文 | 含义 |
|---|---|---|
| 多视角 | multi-view | 共享 3D 场景、不同机位的多张图 |
| 内参/外参 | intrinsics/extrinsics | K（镜头）/ R,t（机位位姿） |
| 对极几何 | epipolar geometry | 两视图对应点的极线约束 |
| 本质矩阵 | essential matrix E | 编码两视图相对位姿的矩阵 |
| 三角化 | triangulation | 两视图匹配点 → 3D 点 |
| 重投影 | reprojection | 3D 点 + 新机位 → 新图像素 |
| 未见区 | unseen / disoccluded region | 输入图没拍到、新机位会露出的面 |
| 新视角合成 | novel view synthesis (NVS) | 从已有视图生成新机位的图 |
| SfM | Structure from Motion | 从多图恢复相机位姿+稀疏 3D 点 |
| 3D 高斯 | 3D Gaussian Splatting | 一种可微渲染的场景表示 |
